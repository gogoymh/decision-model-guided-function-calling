## no-call 인자 검사 생략 (2026-10-17)

- `calls=[]`에서는 Jev에 함수 질문 하나만 보냅니다. 인자 검사는 `arguments_skipped=true`, 판정·확률은 `null`로 기록하며 실패 목록에서 제외합니다. JBFC는 함수 확률과 스키마 기준으로 호출하지 않는 선택을 판단합니다.
- 실제 함수 호출의 `arguments={}`는 생략 조건이 아닙니다. 필수 인자가 없으면 스키마 검사가 거절하며, 읽을 수 있는 호출은 계속 두 Jev 질문을 받습니다.
- 함수 전용 비교는 함수 기준을 유지하고, 인자 전용 비교는 no-call에 스키마 기준만 적용합니다. 빈 호출 거절 후 실제 호출로 수정하거나 그 반대로 수정하는 경로, 누적 피드백, 최종 실행 경계도 확인했습니다.
- 개발 기록의 생략 상태·빈 확률·판정을 재검증하며 위조된 값을 거절합니다. 임계값 분석은 no-call의 함수 확률 하나를 사용하고, 생략한 인자 검사를 인자 Brier 점수의 분모에 포함하지 않습니다.
- 모든 테스트 모듈을 겹치지 않는 두 묶음으로 실행해 총 **391개 오프라인 테스트**가 통과했습니다(변경 관련 243개, 나머지 148개). Ruff와 공백 검사도 통과했습니다. 실제 API 호출은 하지 않았습니다.
- Method의 no-call 설명·수락식·피드백과 비교 방법 설명을 코드에 맞췄으며, 두 검사 오류의 독립성에 관한 문장은 삭제했습니다. 승인된 Abstract와 Introduction은 원문을 보존했습니다. 내장 컴파일과 실제 PDF 내보내기가 성공했고, 본문 4쪽·참고문헌 5쪽 시작과 변경 페이지의 배치를 확인했습니다.
