Function calling maps a request to a function and arguments, or to no call when the available functions are irrelevant. Errors can produce unintended actions: a schema-valid call may select the wrong API, reverse parameter roles, or act unnecessarily. BFCL evaluates names, arguments, and call relevance~\cite{patil2025bfcl}.

For Web agents, deciding whether and how to invoke a service is a reliability boundary between user intent and external action. This work addresses the \emph{Web Infrastructure and Agentic Systems} track: we test whether a separate decision model can improve that boundary before dispatch, while measuring the inference latency and cost of repair. Our benchmarks isolate call prediction rather than validate deployed Web transactions.

Tool-use training improves API selection and generation~\cite{patil2024gorilla,qin2024toolllm}. Inference-time approaches include self-generated feedback~\cite{madaan2023selfrefine}, tool/parameter verification~\cite{mekala2024toolverifier}, tool-error critique~\cite{hamad2025toolcritic}, and reasoning with execution observations~\cite{yao2023react}. Decision models supply targeted judgments: TypeSafe's \textit{Jev} exposes binary checks~\cite{typesafe2026models}, while JEV-as-a-Judge studies acceptance and escalation for completed outputs~\cite{li2026jevjudge}. These precedents motivate testing cumulative feedback before execution.

Three questions guide the study. \textbf{First}, do semantic checks improve on structural repair? Our schema baseline raises call accuracy only from 63.8\% to 65.8\%. \textbf{Second}, do separate function and argument judgments help? Conditional argument scores omit wrong-function and no-call decisions, so we measure full-call correctness and component ablations. \textbf{Third}, does retaining earlier rejections help within the same budget? We compare full history with latest-only feedback while measuring time and cost.

\textbf{Decision-Model-Guided Function Calling (DMFC)} checks function choice and applicable arguments, plus local schemas. Rejected candidates and actual verdicts accumulate before the unchanged request, oldest first; the decision model sees only the current candidate. Only a candidate passing all applicable checks replaces the initial answer. Repair never executes external functions (Figure~\ref{fig:loop}).

We compare two OpenAI generators and Claude with one decision model on BFCL and an API-Bank first-call adaptation, sharing initial candidates in three runs. DMFC improves BFCL accuracy by 10.7 points with nano and 1.0 with mini, but reduces Claude accuracy by 1.3 points. API-Bank gains are 6.4, 1.3, and 0.9 points, respectively; a BFCL ablation finds a 1.1-point benefit from full history. Our contributions are the separate-check cumulative repair design and a paired assessment of accuracy, ablations, and latency--cost trade-offs. API-Bank's input instruction was refined after exploratory outcomes, so this is limited transfer evidence.
