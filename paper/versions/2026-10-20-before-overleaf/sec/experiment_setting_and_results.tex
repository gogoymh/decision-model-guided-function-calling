\subsection{Evaluation and Implementation}
\label{sec:data}
We evaluate 3,051 BFCL examples: simple Python (400), multiple (200), irrelevance (240), live simple (258), live multiple (1,053), live irrelevance (884), and live relevance (16). The AST checker compares names and arguments with allowed answers, not execution success. Irrelevance requires no call. Live relevance scores call presence only and is excluded from the 3,035-example main accuracy. Multiple means selecting among available functions; parallel, multi-turn, web-search, memory, and execution tasks are excluded.

Generators are \texttt{gpt-5-nano-2025-08-07} and \texttt{gpt-5.4-mini} (snapshot 2026-03-17), with reasoning effort \texttt{none} and a 4,096-token output limit. The decision model is \texttt{jev-1.13.0}; $r=3$ and $\tau_f=\tau_a=0.5$. These settings were chosen on the evaluated examples after thresholds 0.8/0.7 and last-candidate fallback; there is no held-out tuning set. Filtered or truncated generations count as incorrect.

\paragraph{Compared methods.}
All methods share initial candidates. \emph{Direct} returns the initial call; \emph{Schema repair} uses local errors; \emph{Self-refine} uses the generator's generic self-review for all $r$ repairs, an adaptation rather than a reproduction of Self-Refine~\cite{madaan2023selfrefine}. \textbf{DMFC-F} uses only function feedback and its acceptance gate; \textbf{DMFC-A} uses only argument feedback and its gate. Both compute applicable judgments but expose and require only their designated judgment, plus schema validation; DMFC-A accepts no call on schema alone. \textbf{DMFC-L} retains only the latest rejected candidate and feedback. Full \textbf{DMFC} retains all records. F/A isolate the two checks; L isolates history retention with the same thresholds, budget, and initial calls.

Figure~\ref{fig:latency} cuts one continued trajectory at each repair limit; these are not independent runs. Increasing $r$ from 3 to 10 raises accuracy from 74.6\% to 76.7\%, mean API time from 2.61 to 4.29~s, and p95 from 6.83 to 17.72~s; cost grows from \$0.211 to \$0.399 per 1,000 requests. \paragraph{Fallback and measurement limits.}
Returning the initial rather than the last unaccepted candidate changes mean accuracy by $+1.37$ points (95\% interval 0.93--1.82) for \texttt{gpt-5.4-mini}, but $-0.35$ ($-0.68$ to $-0.03$) for \texttt{gpt-5-nano}. API time sums generation and verification durations, excluding retry waits, scoring, and external-tool execution. Cost includes shared initial generation, growing-history generation, and verification; one filtered response without usage is excluded from cost. Intervals use 2,000 paired example-ID bootstrap samples (seed 1729). Two generators, one decision model, one ablation run, mostly English requests, public-data contamination, ten retained annotation errors, and tuning on evaluation examples limit generalization. Acceptance can introduce errors and is reported separately from correctness.
